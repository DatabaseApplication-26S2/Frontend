### Configure setup project dependency and storageState in playwright.config.ts

Source: https://github.com/microsoft/playwright/blob/v1.64.1/docs/src/auth.md

Declares a setup project matching *.setup.ts and makes the chromium and firefox projects depend on it, reusing the saved storageState. The setup project always runs and authenticates before the testing projects.

```js
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  projects: [
    // Setup project
    { name: 'setup', testMatch: /.*\.setup\.ts/ },

    {
      name: 'chromium',
      use: {
        ...devices['Desktop Chrome'],
        // Use prepared auth state.
        storageState: 'playwright/.auth/user.json',
      },
      dependencies: ['setup'],
    },

    {
      name: 'firefox',
      use: {
        ...devices['Desktop Firefox'],
        // Use prepared auth state.
        storageState: 'playwright/.auth/user.json',
      },
      dependencies: ['setup'],
    },
  ],
});
```

### Configuring webServer in playwright.config.ts

Source: https://github.com/microsoft/playwright/blob/v1.64.1/docs/src/release-notes-js.md

Launches a local development server prior to test execution and waits for the specified URL to become available. The URL is automatically passed to Playwright as the baseURL when creating browser contexts.

```js
import { defineConfig } from '@playwright/test';
export default defineConfig({
  webServer: {
    command: 'npm run start', // command to launch
    url: 'http://127.0.0.1:3000', // url to await for
    timeout: 120 * 1000,
    reuseExistingServer: !process.env.CI,
  },
});
```

### Configure and use baseURL for relative navigation

Source: https://github.com/microsoft/playwright/blob/v1.64.1/docs/src/test-webserver-js.md

Set baseURL in playwright.config.ts to allow test actions like page.goto to automatically resolve against the base URL using relative paths.

```javascript
import { defineConfig } from '@playwright/test';

export default defineConfig({
  // Rest of your config...

  // Run your local dev server before starting the tests
  webServer: {
    command: 'npm run start',
    url: 'http://localhost:3000',
    reuseExistingServer: !process.env.CI,
  },
  use: {
    baseURL: 'http://localhost:3000',
  },
});
```

```javascript
import { test } from '@playwright/test';

test('test', async ({ page }) => {
  // This will navigate to http://localhost:3000/login
  await page.goto('./login');
});
```

### TestConfig > property: TestConfig.webServer > Details

Source: https://github.com/microsoft/playwright/blob/v1.64.1/docs/src/test-api/class-testconfig.md

If the port is specified, Playwright Test will wait for it to be available on `127.0.0.1` or `::1`, before running the tests. If the url is specified, Playwright Test will wait for the URL to return a 2xx, 3xx, 400, 401, 402, or 403 status code before running the tests.

For continuous integration, you may want to use the `reuseExistingServer: !process.env.CI` option which does not use an existing server on the CI. To see the stdout, you can set the `DEBUG=pw:webserver` environment variable.

The `port` (but not the `url`) gets passed over to Playwright as a [`property: TestOptions.baseURL`]. For example port `8080` produces `baseURL` equal `http://localhost:8080`. If `webServer` is specified as an array, you must explicitly configure the `baseURL` (even if it only has one entry).
