### Common mistakes with Unicode tokens

Source: https://github.com/date-fns/date-fns/blob/v4.4.0/pkgs/core/docs/unicodeTokens.md

Shows incorrect and correct usage of `format` and `parse` with day-of-year vs day-of-month and week-year vs calendar-year tokens. The wrong examples produce unexpected results, while the correct ones yield the intended dates.

```javascript
// ❌ Wrong!
format(new Date(), "YYYY-MM-DD");
//=> 2018-10-283
```

```javascript
// ✅ Correct
format(new Date(), "yyyy-MM-dd");
//=> 2018-10-10
```

```javascript
// ❌ Wrong!
parse("11.02.87", "D.MM.YY", new Date()).toString();
//=> 'Sat Jan 11 1986 00:00:00 GMT+0200 (EET)'
```

```javascript
// ✅ Correct
parse("11.02.87", "d.MM.yy", new Date()).toString();
//=> 'Wed Feb 11 1987 00:00:00 GMT+0200 (EET)'
```

### Using options to enable ambiguous tokens

Source: https://github.com/date-fns/date-fns/blob/v4.4.0/pkgs/core/docs/unicodeTokens.md

Shows how to use `useAdditionalDayOfYearTokens` and `useAdditionalWeekYearTokens` options to allow `D`, `DD`, `YY`, and `YYYY` tokens in `format` and `parse`. Without these options, the functions will not accept these tokens.

```javascript
format(new Date(), "D", { useAdditionalDayOfYearTokens: true });
//=> '283'
```

```javascript
parse("365+1987", "DD+YYYY", new Date(), {
  useAdditionalDayOfYearTokens: true,
  useAdditionalWeekYearTokens: true,
}).toString();
//=> 'Wed Dec 31 1986 00:00:00 GMT+0200 (EET)'
```

### Creating a locale wrapper for format

Source: https://github.com/date-fns/date-fns/blob/v4.4.0/pkgs/core/docs/i18n.md

Demonstrates a wrapper function that uses a global locale ID to format dates with the appropriate locale. It shows the output for English and Esperanto, and the default format string behavior.

```javascript
// app/_lib/format.js

import { format } from "date-fns";
import { enGB, eo, ru } from "date-fns/locale";

const locales = { enGB, eo, ru };

// by providing a default string of 'PP' or any of its variants for `formatStr`
// it will format dates in whichever way is appropriate to the locale
export default function (date, formatStr = "PP") {
  return format(date, formatStr, {
    locale: locales[window.__localeId__], // or global.__localeId__
  });
}

// Later:

import format from "app/_lib/format";

window.__localeId__ = "enGB";
format(friday13, "EEEE d");
//=> 'Friday 13'

window.__localeId__ = "eo";
format(friday13, "EEEE d");
//=> 'vendredo 13'

// If the format string is omitted, it will take the default for the locale.
window.__localeId__ = "enGB";
format(friday13);
//=> Jul 13, 2019

window.__localeId__ = "eo";
format(friday13);
//=> 2019-jul-13
```

### dateFormats example for en-US locale

Source: https://github.com/date-fns/date-fns/blob/v4.4.0/pkgs/core/docs/i18nContributionGuide.md

Defines the `dateFormats` object for the `en-US` locale, using CLDR 'Date & Time'/'Gregorian'/'Formats - Standard - Date Formats' values. The `formatLong.date` is built with `buildFormatLongFn`, defaulting to `full` width. `dateFormats.long` typically contains the longest form of year, month, and day; `full` adds the day of the week; `medium` uses short month and non-ordinal day; `short` is strictly numerical. Use ordinal day ('do') where applicable.

```javascript
// In `en-US` locale
import buildFormatLongFn from "../../../_lib/buildFormatLongFn/index.js";

var dateFormats = {
  full: "EEEE, MMMM do, y",
  long: "MMMM do, y",
  medium: "MMM d, y",
  short: "MM/dd/yyyy",
};

var formatLong = {
  date: buildFormatLongFn({
    formats: dateFormats,
    defaultWidth: "full",
  }),
  // ...
};

export default formatLong;
```

### Usage with formatDistance and subDays

Source: https://github.com/date-fns/date-fns/blob/v4.4.0/pkgs/core/docs/gettingStarted.md

Demonstrates using formatDistance and subDays to calculate relative time, with the addSuffix option to produce output like '3 days ago'. Expects the date to be three days in the past.

```javascript
import { formatDistance, subDays } from "date-fns";

formatDistance(subDays(new Date(), 3), new Date(), { addSuffix: true });
//=> "3 days ago"
```
