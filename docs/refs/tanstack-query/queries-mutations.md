### Implement React Query Core Concepts (Queries, Mutations, Invalidation) in TypeScript/React

Source: https://github.com/tanstack/query/blob/v5.90.3/docs/framework/react/quick-start.md

This snippet demonstrates the fundamental usage of `@tanstack/react-query` in a React application. It showcases how to set up `QueryClientProvider`, define a query using `useQuery` to fetch data, and perform a mutation using `useMutation` with an `onSuccess` callback to invalidate and refetch queries after a successful data update.

```tsx
import {
  useQuery,
  useMutation,
  useQueryClient,
  QueryClient,
  QueryClientProvider,
} from '@tanstack/react-query'
import { getTodos, postTodo } from '../my-api'

// Create a client
const queryClient = new QueryClient()

function App() {
  return (
    // Provide the client to your App
    <QueryClientProvider client={queryClient}>
      <Todos />
    </QueryClientProvider>
  )
}

function Todos() {
  // Access the client
  const queryClient = useQueryClient()

  // Queries
  const query = useQuery({ queryKey: ['todos'], queryFn: getTodos })

  // Mutations
  const mutation = useMutation({
    mutationFn: postTodo,
    onSuccess: () => {
      // Invalidate and refetch
      queryClient.invalidateQueries({ queryKey: ['todos'] })
    },
  })

  return (
    <div>
      <ul>
        {query.data?.map((todo) => (
          <li key={todo.id}>{todo.title}</li>
        ))}
      </ul>

      <button
        onClick={() => {
          mutation.mutate({
            id: Date.now(),
            title: 'Do Laundry',
          })
        }}
      >
        Add Todo
      </button>
    </div>
  )
}

render(<App />, document.getElementById('root'))
```

### Invalidate Queries on Mutation Success with onSuccess Callback

Source: https://github.com/tanstack/query/blob/v5.90.3/docs/framework/react/guides/invalidations-from-mutations.md

Demonstrates how to invalidate single or multiple queries when a mutation succeeds using the onSuccess callback. Returns a Promise to ensure data is updated before the mutation completes. Imports useMutation and useQueryClient from @tanstack/react-query.

```typescript
import { useMutation, useQueryClient } from '@tanstack/react-query'

const queryClient = useQueryClient()

// When this mutation succeeds, invalidate any queries with the `todos` or `reminders` query key
const mutation = useMutation({
  mutationFn: addTodo,
  onSuccess: async () => {
    // If you're invalidating a single query
    await queryClient.invalidateQueries({ queryKey: ['todos'] })

    // If you're invalidating multiple queries
    await Promise.all([
      queryClient.invalidateQueries({ queryKey: ['todos'] }),
      queryClient.invalidateQueries({ queryKey: ['reminders'] }),
    ])
  },
})
```

### Setup useMutation with onSettled for optimistic updates

Source: https://github.com/tanstack/query/blob/v5.90.3/docs/framework/react/guides/optimistic-updates.md

Configures a mutation with onSettled handler to invalidate queries after mutation completes. Returns a Promise from query invalidation to keep mutation in pending state until refetch finishes. Provides access to mutation state including isPending, variables, and isError for UI updates.

```typescript
const addTodoMutation = useMutation({
  mutationFn: (newTodo: string) => axios.post('/api/data', { text: newTodo }),
  // make sure to _return_ the Promise from the query invalidation
  // so that the mutation stays in `pending` state until the refetch is finished
  onSettled: () => queryClient.invalidateQueries({ queryKey: ['todos'] }),
})

const { isPending, submittedAt, variables, mutate, isError } = addTodoMutation
```

### Invalidations from Mutations

Source: https://github.com/tanstack/query/blob/v5.90.3/docs/framework/react/guides/invalidations-from-mutations.md

When a successful `postTodo` mutation happens, it's often desirable for all related queries, such as `todos` queries, to be invalidated and potentially refetched to reflect the new data. This can be achieved by leveraging `useMutation`'s `onSuccess` option in conjunction with the `queryClient`'s `invalidateQueries` function. By returning a Promise within `onSuccess`, you ensure that the data update process completes before the mutation is considered entirely finished, meaning the `isPending` state remains true until the `onSuccess` Promise is fulfilled. Furthermore, query invalidations can be configured to occur using any of the available callbacks provided by the [`useMutation` hook](../mutations.md).

### Query Invalidation > Query Matching with `invalidateQueries`

Source: https://github.com/tanstack/query/blob/v5.90.3/docs/framework/react/guides/query-invalidation.md

When using APIs like `invalidateQueries` and `removeQueries` that support partial query matching, you have flexible options for targeting queries. You can match multiple queries by their prefix in the query key, or you can be very specific and match an exact query. For instance, you can invalidate all queries whose keys start with `todos`, or target queries with specific variables by providing a more detailed query key. For even greater precision, the `exact: true` option can be used to invalidate only queries that precisely match the provided query key, ignoring any subkeys or additional variables. For the highest level of granularity, a predicate function can be passed to `invalidateQueries`, allowing you to define custom logic to evaluate each `Query` instance from the cache and decide whether it should be invalidated.
