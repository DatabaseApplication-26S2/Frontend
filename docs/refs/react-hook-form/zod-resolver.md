### zodResolver

Source: https://github.com/react-hook-form/resolvers/blob/master/_autodocs/api-reference/zod.md

Factory function that adapts a Zod 3 or Zod 4 schema to a react-hook-form Resolver. Supports both major versions via feature detection and uses the schema's own bound parse methods to respect global config.

### Parameters

#### schema
- **Type**: `Zod3Type<Output, Input>` or `Zod4Type<Output, Input>`
- **Required**: Yes
- **Description**: The Zod schema to adapt. Zod 3 schemas have an object-shaped `_def` marker; Zod 4 schemas have an object-shaped `_zod` marker.

#### schemaOptions
- **Type**: `Zod3ParseParams` or `Zod4ParseParams` (optional)
- **Required**: No
- **Description**: Parse options passed to the schema's `parse`/`parseAsync` method. For Zod 3, includes `path`, `errorMap`, and `async`. For Zod 4, includes `error`, `reportInput`, and `jitless`.

#### resolverOptions
- **Type**: `{ mode?: 'async' | 'sync'; raw?: boolean }` (optional)
- **Required**: No
- **Description**: Options for the resolver. `mode` sets the validation mode; `raw` when true returns the raw input type instead of the output type.

### Return Value
Returns a `Resolver<Input, Context, Output>` or `Resolver<Input, Context, Input>` depending on the overload and `raw` option.

### Notes
- The schema's own bound `parse`/`parseAsync` methods are used, not the standalone `z4.parse` functions, to respect global config (`z.config()`) even under bundlers with duplicate module instances.
- The `Zod3Type`/`Zod4Type` interfaces use minimal shapes to stay assignable across zod versions.
- `UnresolvedFallback` allows parse-param types to degrade gracefully on zod < 3.25.0.

### Basic usage with zodResolver

Source: https://github.com/react-hook-form/resolvers/blob/master/_autodocs/api-reference/zod.md

Use zodResolver with a Zod schema in react-hook-form. Import z from 'zod' or 'zod/v4'. The resolver validates form data against the schema and exposes errors via formState.

```tsx
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';

const schema = z.object({
  name: z.string().min(1, { message: 'Required' }),
  age: z.number().min(10),
});

const App = () => {
  const { register, handleSubmit, formState: { errors } } = useForm({
    resolver: zodResolver(schema),
  });
  return (
    <form onSubmit={handleSubmit((d) => console.log(d))}>
      <input {...register('name')} />
      {errors.name?.message && <p>{errors.name?.message}</p>}
      <input type="number" {...register('age', { valueAsNumber: true })} />
      {errors.age?.message && <p>{errors.age?.message}</p>}
      <input type="submit" />
    </form>
  );
};
```

### Zod resolver — zodResolver

Source: https://github.com/react-hook-form/resolvers/blob/master/_autodocs/api-reference/zod.md

Import path: `@hookform/resolvers/zod` (from `zod/src/index.ts`, which is `export * from './zod';`).

Factory that adapts a Zod 3 or Zod 4 schema to a react-hook-form `Resolver`. Supports both major versions at runtime via feature detection: a schema is treated as Zod 4 when it has an object-shaped `_zod` marker (`isZod4Schema`, checked first), otherwise as Zod 3 when it has an object-shaped `_def` (`isZod3Schema`). The schema's own bound `parse`/`parseAsync` methods are used (not the standalone `z4.parse` functions) so that global config (`z.config()`) from the app's zod instance is respected even under bundlers that resolve duplicate module instances.

Source file: `zod/src/zod.ts`. Public overloads at lines 232–256; implementation at line 282.
