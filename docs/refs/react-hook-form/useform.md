### setError

Source: https://react-hook-form.com/docs/useform/seterror

Sets a single error for a specific input field or a global/server error. This method is part of the useForm hook and can be called to manually set validation errors.

```APIDOC
## setError

### Description
Sets a single error for a specific input field or a global/server error. This method is part of the useForm hook and can be called to manually set validation errors.

### Method
setError

### Signature
setError(name, error, config?)

### Parameters
- **name** (string) - Required - The name of the input field or 'root.serverError' for global errors.
- **error** (object) - Required - An object containing `type` (string) and optional `message` (string).
- **config** (object) - Optional - Configuration object with `shouldFocus` (boolean) to focus the input.

### Behavior
- Does not persist error if input passes register's validation rules.
- Errors not associated with an input persist until cleared with `clearErrors`.
- Since v7.43.0, can set server/global errors with `root` key.
- `shouldFocus` does not work on disabled inputs.
- Forces `formState.isValid` to `false`.
- Avoid using reserved field names: `type`, `root`, `ref`, `types`, `message`, `form`.

### Examples

#### Single Error (TypeScript)
```tsx
import { useEffect } from "react"
import { useForm } from "react-hook-form"

type FormInputs = {
  username: string
}

const App = () => {
  const {
    register,
    handleSubmit,
    setError,
    formState: { errors },
  } = useForm<FormInputs>()
  const onSubmit = (data: FormInputs) => {
    console.log(data)
  }

  useEffect(() => {
    setError("username", {
      type: "manual",
      message: "Dont Forget Your Username Should Be Cool!",
    })
  }, [setError])

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input {...register("username")} />
      {errors.username && <p>{errors.username.message}</p>}

      <input type="submit" />
    </form>
  )
}
```

### handleSubmit(onValid, onInvalid?)

Source: https://react-hook-form.com/docs/useform/handlesubmit

Validates form inputs and invokes the submit callback with typed form data, or passes errors to an error handler on validation failure. Returns a promise that resolves with the result of the submit handler.

```APIDOC
## handleSubmit(onValid, onInvalid?)

### Description
Validates form inputs and invokes the submit callback with typed form data, or passes errors to an error handler on validation failure. Returns a promise that resolves with the result of the submit handler.

### Method
Function call

### Signature
`handleSubmit: (onValid: SubmitHandler, onInvalid?: SubmitErrorHandler) => (e?: BaseSyntheticEvent) => Promise<TResult | undefined>`

### Parameters
#### Callback Parameters
- **SubmitHandler** (`(data: TFieldValues, e?: BaseSyntheticEvent) => TResult | Promise<TResult>`) - Required - A successful callback.
- **SubmitErrorHandler** (`(errors: FieldErrors, e?: BaseSyntheticEvent) => unknown | Promise<unknown>`) - Optional - An error callback.

### Return Value
Returns a function that accepts an optional event and returns a promise resolving with the result of the submit handler (or `undefined` if no handler returns a value).

### Rules
- The promise returned by `handleSubmit(onValid)(event)` resolves with whatever `onValid` returns (since v7.84.0).
- `formState.isSubmitting` stays `true` until the promise returned by `onSubmit` settles.
- `disabled` inputs appear as `undefined` in form values.
- `handleSubmit` does not swallow errors from the submit callback; use try/catch and `setError` for server errors.
- To submit from a button outside the form, use the native `form` attribute or call the returned function directly.
- Stop propagation if a form is nested inside another form.

### Request Example
```javascript
const onValid = (data) => ({ id: data.id })
const result = await handleSubmit(onValid)() // result: { id: string } | undefined
```

### Request Example
```javascript
const onSubmit = async (data) => {
  await fetch("/api", { method: "POST", body: JSON.stringify(data) }) // ✅ isSubmitting stays true until this resolves
}
```

### Request Example
```javascript
const onSubmit = async (data) => {
  // async request which may result error
  try {
    // await fetch()
  } catch (e) {
    setError("root.serverError", {
      type: e.status,
      message: e.message,
    })
  }
}

return <form onSubmit={handleSubmit(onSubmit)} />
```

### Request Example
```javascript
<form id="profile-form" onSubmit={handleSubmit(onSubmit)}>...</form>

<button type="submit" form="profile-form">Save</button> // ✅ native form attribute
<button type="button" onClick={handleSubmit(onSubmit)}>Save</button> // ✅ call handleSubmit directly
```

### Request Example
```javascript
<form
  onSubmit={(event) => {
    event.stopPropagation()
    handleSubmit(onInnerSubmit)(event)
  }}
/>
```

### Handle errors in onSubmit with setError

Source: https://react-hook-form.com/docs/useform/handlesubmit

handleSubmit does not swallow errors from onSubmit, so use try/catch inside async requests. Use setError inside the catch block to register a server-side error, which also sets formState.isSubmitSuccessful to false.

```javascript
const onSubmit = async (data) => {
  // async request which may result error
  try {
    // await fetch()
  } catch (e) {
    setError("root.serverError", {
      type: e.status,
      message: e.message,
    })
  }
}

return <form onSubmit={handleSubmit(onSubmit)} />
```

### useForm > setError

Source: https://react-hook-form.com/docs/useform/seterror

> **Important: Rules**
>
> - This method will not persist the associated input error if the input passes `register`'s associated rules.
>   ```javascript
>   register("registerInput", { minLength: 4 })
>   setError("registerInput", { type: "custom", message: "custom message" })
>   // validation will pass as long as minLength requirement pass
>   ```
> - An error that is not associated with an input field will be persisted until cleared with `clearErrors`. This behavior is only applicable for built-in validation at the field level.
>   ```javascript
>   setError("notRegisteredInput", { type: "custom", message: "custom message" })
>   // clearErrors() needs to be invoked manually to remove that custom error
>   ```
> - _(since v7.43.0)_ You can set a server or global error with `root` as
>   the key. This type of error will not persist with each submission.
>
> ```javascript
> setError("root.serverError", {
>   type: "400",
> })
> ```
>
> - `shouldFocus` doesn't work when an input has been disabled.
> - This method will force <code>formState.isValid</code> to <code>false</code>.
>   However, <code>isValid</code> is always derived from the validation results of your
>   registered inputs or schema.
> - Avoid using `type`, `root`, `ref`, `types`, `message`, or `form` as field names — these collide with the internal shape of `FieldError`/`GlobalError`.
